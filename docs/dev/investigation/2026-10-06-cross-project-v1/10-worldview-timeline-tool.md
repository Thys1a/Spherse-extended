# 对象 E 对照调研：世界观设定与时间轴管理工具

调研时间：2026-10-18
对象：公开 Web App（腾讯 CloudBase 静态托管，无框架 vanilla JS + localStorage，`?v=20261003i`）+ 对照 Spherse 现状
定位前提：**两项目独立并行**，本调研只回答三件事——重合在哪、哪些是重复投入、哪些对 Spherse 有启发。不主张合并，不产出 backlog / design 变更。

调研手段与局限：直读 Web App HTML 外壳（路由/导航/数据模型/资源清单全在首屏 HTML 内）+ meta 描述；Jina Reader 因出口 IP 信誉被拒（401），Exa 搜索被同名影视与 AI 产品噪声淹没、无有效仓库/文档结果；SPA 深层交互（需登录态的上层数据）未深挖。以下结论以「内核 / 预设分层」为限，不涉及对象 E 后端实现猜测。

## 一、结论摘要

1. **它是对象 A 的“设定侧”子集的产品化**：对象 A 是长篇叙事创作副驾驶（写），对象 E 是世界观设定与时间轴管理工具（记）。对象 E ≈ 对象 A 的 FactCard/名词库/时间轴那半 + 版本管理 + 对外接口，独立成 Web App。
2. **重合在世界书与检索，不在运行时**：实体条目/统一名词库 ↔ Spherse `.card.json` worldbook；顶栏常驻全文检索 ↔ Spherse `Ctrl+P` 全局搜索。Spherse 是通用 Agent 运行时，对象 E 是单机 CRUD 应用，无 Agent/编排/自动化。
3. **最值得借鉴的只有一条，且正中当前缺口**：顶栏常驻搜索框 + `⌘K` 的显式搜索入口——与 `docs/dev/bugfix/2026-10-17-ui-triage` issue 3（搜索功能完成但零显式 UI）是同一问题的正反两面。
4. 其余借鉴点（待确认队列、冲突校验、显示范围）均为 Workspace/预设层模式，不进内核；三层叙事数据模型、OC/哥特垂直能力明确不吸收。

## 二、它是什么

一句话：面向内容创作者的本地优先世界观设定管理工具——三层数据架构、全局主时间轴、冲突校验、大事件自动组合、智能整理、辅助创作与标准开发接口（meta 原文）。

| | 对象 E | Spherse |
|---|---|---|
| 一句话 | 世界观设定与时间轴管理（记） | 本地个人 Agent 运行时（跑任意 Workspace） |
| 形态 | 单文件级 SPA：原生 JS（`data/store/engine/ai/api/ui/app` 等 ~20 个脚本直引）+ 多 CSS，腾讯 CloudBase 静态托管 | Electron + React + Fastify 三端 |
| 状态/存储 | `localStorage`（主题等偏好键）为主，登录模块存在但登录后行为未知 | 项目目录 + SQLite（sessions）+ electron-store |
| 数据模型（三层） | 世界库 → 世界 → 大类（横向导航）→ 条目（人物/势力/地点…）；正交维度：时间轴事件、大事件 saga、名词库词条、已有故事、OC | 项目 → agent/session/skill/MCP；`.card.json`（worldbook）+ `.data.json` + 文件 |
| AI 位置 | 智能整理（analyze）、AI 共创（forge）、辅助创作（assist）、灵感（inspiration），产出先进**待确认队列**再落库 | Agent 主循环直写，`withApproval` 卡点审批 |
| 对外协议 | 「开发接口」视图（标准接口，细节未读） | MCP **client**（对象 A 是 server 方向） |
| 检索 | 顶栏常驻全文检索（人物/事件/地点/名词）+ `⌘K` | `Ctrl+P` 全局搜索 + `Ctrl+F` 会话内查找，均无常驻入口 |
| 版本 | 版本管理 + 数据备份/恢复 + 导入导出 | backlog「git 版本控制」（未做） |
| 美学 | 哥特暗黑 + 日夜主题 + 世界树导航 + OC 关系板 | agent theme / skill 主题机制 |

## 三、能力重合矩阵

| 能力 | 对象 E 实现 | Spherse 实现 | 判定 |
|---|---|---|---|
| 实体/名词库 | 实体条目 + 统一名词库（`glossary` 路由） | `.card.json` worldbook + 关键词注入 | 理念一致，载体不同 |
| 全文检索 | 顶栏常驻 + `⌘K`，覆盖人物/事件/地点/名词 | `Ctrl+P`（聊天+文件名），无可见入口 | **对象 E 可发现性更强** |
| 时间轴 | 全局主时间轴 + 时间轴事件（`timeline` 路由） | 无（01 多线时间线工具未吸收） | 对象 E 独有 |
| 大事件组合 | 手动组合 + 自动聚合（`sagas` 路由） | 无等价物 | 对象 E 独有 |
| 冲突校验 | 冲突预警常驻分组（`conflictMini`） | 无 | 对象 E 独有 |
| HITL | 待确认队列（批量条目级，`pending` 路由 + 顶栏 badge） | `withApproval` 审批卡（单次 action 级） | 各有实现，粒度不同 |
| 显示范围 | `scopeBox` 按大类过滤显示/注入 | 世界书逐条 depth/role（06 §五 #4，待评估） | 互相印证 |
| 版本/备份 | 版本管理 + 备份/恢复 + 导入导出 | backlog「git 版本控制」（未做） | 印证 backlog 条目 |
| 开发接口 | `api` 路由（标准接口） | MCP client；对象 A 是 server 方向 | 对照参考，方向待定 |
| 世界树导航 | 大类 → 条目层级树 | 文件树 / 项目面板 | 目标同，载体不同 |
| OC 关系板 | `oc-board` | 力导向图预设参考（01 §七 #6） | 互印证 |
| 多世界隔离 | 世界库多世界 | ProjectRegistry 多项目 | 两者皆有 |
| 本地优先 | 静态托管 + localStorage | 项目目录本地存储 | 理念一致 |

## 四、可借鉴点（按价值排序）

1. **显式搜索入口（唯一建议跟进的一项）**：顶栏常驻搜索框 + `⌘K` 快捷键 + 移动端可展开搜索。Spherse 两套搜索全隐式（triage issue 3），对象 E 证明了“检索框常驻”在同类信息密度应用里是标准解。落点：app Header/工具栏（i18n 复用 `content-browser.find.*` / `global-search.search`），不涉及检索后端改动。
2. **待确认队列模式**：AI 批量产出（整理/组合/聚合）先进队列、逐条确认再落库，顶栏 badge 计数。Spherse 审批卡是单次 action 级；队列是批量条目级，可作为「AI 产出结构化修改建议」卡片范式的第二种形态（呼应 01 §七 #3 审查建议卡），落点为 UI SDK/预设层。
3. **冲突校验**：实体 × 时间轴 × 名词库三层交叉一致性检查（人名不统一、事件时间矛盾）。Spherse 无；叙事 Workspace 可用 skill + trigger 定时实现，不进内核。
4. **大事件自动组合**：时间轴事件按关联聚合成 saga。通用化即「事件聚类/摘要」，与 compaction fold 思想同源、实现层不同，调查参考、不移植。
5. **显示范围 scope**：按大类圈定显示/注入子集，与 06 §五 #4（世界书逐条 depth/role）、`2026-10-11-state-data-link` 的「子集化」互相印证，走通用机制、不单独立项。
6. **版本管理/备份**：印证 backlog「git 版本控制」条目仍成立，无新增信息。
7. **开发接口**：若其读接口稳定，可作为「叙事 Workspace 对外只读」的对照样本（与对象 A MCP server 方向并列）；Spherse 侧无动作。

## 五、明确不建议

- **不把三层叙事数据模型做进 Spherse 内核**：世界库/大类/条目/saga/名词库是垂直 schema，Spherse 已有通用 `.card.json`/`.data.json`，预设模板层覆盖即可（同 01 §四裁决）。
- **不照搬技术栈**：vanilla JS + localStorage 与 Spherse 的 TS/Electron/SQLite 体系不兼容；其“无后端”也意味着多端同步、冲突解决等坑由用户自担，不适合反向参考。
- **不吸收 OC/哥特垂直能力**：原创角色板、暗黑美学主题是产品差异化，不是平台机制。
- **不因对象 E 有时间轴而给 Spherse 加时间轴**：01 §五已裁决多线时间线是 Workspace 预设选题；对象 E 只增加了一个现成的信息架构参考（主时间轴 + 大事件库 + 待确认队列的三件套），不等同于新需求。
