## 一、删除后仍显示：全链路核查结论

### 1. 已证实无问题的链路

- 编辑器删除进 form state：`QuickReplyField` X → `onRemove(index)` → `AgentDialogForm.tsx:111` `filter`（按下标，非按 label，重名安全）。
- 保存全量覆写：空数组时 `buildAgentMarkdown` 省略 key（`agent-markdown.ts:153-155`）→ PUT → `routes/agent-write.ts:37` → `project-runtime.ts:99-100` → `project-manager.ts:95-98` → `project.ts:223-232` → `agent-store.ts:58-62` 写文件 + 刷新内存 `_profile`。`parseFile` 无合并逻辑。
- 服务端读写同一实例：`registry.ts:111-123`，`ctx.projectManager` 即 `runtime.projectManager`（单例，无双缓存分叉）。
- 前端失效覆盖 displaying query：`updateProjectAgent`（`queries/project/agents.ts:82-95`）清三个 key，含 Chat 用的明细 key（`agent()`）；`useProjectAgentProfile`（`:23-34`）即该 key。单例 `queryClient`（`queries/client.ts:16`）与 `main.tsx:24` provider 同实例；`staleTime: Infinity` 下 `invalidateQueries` 照常重取活跃 query。
- 渲染单消费方：`chat/index.tsx:314-315` 条件与数据同源 `profileQuery.data`，无第二渲染路径。
- 安装包：`app.asar` 内含 `data-chat-quick-replies` / `quickReplies` / `resolveAppUserModelId`（二进制直查命中）；任务栏固定目录无 Spherse 残留；当前 6 个进程全为 `D:\note\Spherse\Spherse.exe`，无 `electron.exe`。

### 2. 结论

静态可达路径全部自洽，**未发现必现根因**。剩余按可能性排序：

1. （最可能）删的是 A，看的是 B：所编辑 agent 与所看会话的 agent 不是同一个；或删的是重名 label 其中一条，另一条同名仍在。
2. 保存实际失败：PUT 抛错时对话框**停留并显示错误**（`agent-session-list/index.tsx:111-114`，`ok=false` 不关闭）。若未注意错误就关掉对话框，等于没删。
3. 瞬时：失效→重取异步，肉眼快照早于回包（切一次会话即消失可证伪）。
4. 重取静默失败：React Query 保留旧数据。排查看 `GET /api/projects/:id/agents/:agentId` 返回体。

### 3. 确认三步（按顺序做，定位到哪步停）

1. 保存后打开 `.spherse/agents/<slug>/profile.md` 看 `quickReplies` 是否已变 → 不变 = 写链问题（把 dialog 错误文案贴出来）；变了 → 往下。
2. 查“看的是不是同一个 agent”：在聊天窗口记下 header 的 agent 名，再到项目目录全文搜那条回复的文字，看它到底躺在哪个 agent 的 `profile.md` 里（PowerShell，在**自己的项目目录**执行）：
   `Select-String -Path ".spherse\agents\*\profile.md" -Pattern "quickReplies"`，再对命中的文件搜具体 label。若在另一个 agent/项目里 = 删错了地方；若哪儿都没有 → 往下。
3. 若文件里没有、别的 agent 里也没有，但重开窗口仍显示：把 profile.md 内容和看到的条目截图贴出来，转真机复现（此时再考虑调 API 查 `GET /api/projects/:id/agents/:agentId` 返回体）。

2026-10-19 补充（用户反馈）：profile.md 确认无 `quickReplies` 且重开窗口仍显示 → 写链嫌疑排除，“删错 agent / 看错会话”升为首要嫌疑；API 对账后移到“文件与 UI 都对不上时”才做。

2026-10-19 结论（用户澄清后结案，非 bug）：用户实际操作是“添加并保存 → 打开编辑删掉徽章 → **没点保存**”。编辑页无自动保存（唯一写路径是保存按钮 → PUT），删徽章只改了对话框本地草稿，服务端文件与查询均未变，故聊天窗口继续显示且可点——**符合预期**。附带澄清：之前“profile 无匹配”是打开错文件＋VSCode 搜错了目录；目标文件第 29 行确有所加条目。另暴露一个体验缺口（未立项）：对话框关闭无未保存校验，删了不保存直接关，视觉上像“删了没生效”——是否要加 dirty 守卫待定。

## 二、管理弹窗提案（2026-10-19 已定稿并实现）

- 落定形态：入口只在 agent 编辑 → 个性化 → 快捷回复行（`共 N 条` + 「管理」，空态也在，不往聊天窗口/agent 菜单/Header 放）。
- `QuickReplyManagerDialog`（`features/agent-dialog/`）：props 取 `replies` + `onChange` + `onClose`，只改编辑页草稿，不碰磁盘/API；落盘唯一路径仍是编辑页保存。`QuickReplyField.tsx` 收敛为入口行组件（原内联编辑逻辑并入弹窗，原用例迁移）。
- 完整 CRUD 在弹窗内：增/行内改（预填+更新，不经过删后重加）/删；上限 10 条、`label` 16 字、`description`/`text` 规则沿用。
- 不做：直发、开关、全局集（沿用 design 已决策）；`action` 仍仅 `fill`。
- 测试：弹窗增/改/删/上限/空态/关闭 + 行组件入口 + 编辑页 wiring 不变（既有用例全过）。
- 附带发现（预存问题，非本次引入）：`buildAgentMarkdown` 保存时会丢弃 `timePerception: {enabled:false}` 配置，见 backlog 新条目。
